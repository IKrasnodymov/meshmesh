# Регионы MeshCore

Регион (region, flood scope) ограничивает, куда расходятся flood-пакеты. Узел помечает пакет
транспортным кодом региона, а репитеры с настроенными регионами пересылают его, только если обслуживают
этот регион. Пакет без региона считается общим: его пересылают репитеры, у которых разрешён `*`
(`region allowf *`). Регионы есть в MeshCore 1.10+; синтаксис `region def` — с 1.16.

Код — первые 2 байта HMAC-SHA256 с ключом региона по байту типа и полезной нагрузке пакета. Ключ
публичного региона — первые 16 байт SHA-256 от строки `#имя` (`msk` → SHA-256(`#msk`)). Имя
чувствительно к регистру, как на репитерах: `msk` и `MSK` — разные регионы. Регион с `$` в начале
закрытый: ключ из имени не выводится, его задаёт только приложение MeshCore.

Код: `include/Regions.h`, `src/Regions.cpp`, поиск — `src/RegionSearch.inc`, отправка —
`MeshCoreBackend::floodScoped` и `MeshRadio::scopeKey` в `src/MeshRadio.cpp`.

## Обычный режим (чаты)

Какой регион получает flood-пакет узла (сообщения, ACK, возвраты пути, запросы к репитерам и комнатам,
объявления):

1. Пока подключено приложение MeshCore и оно выбрало регион сеанса (`CMD_SET_FLOOD_SCOPE_KEY`) — этот
   регион или «без региона». После отключения приложения выбор сбрасывается.
2. Сообщение канала — регион канала: свой, «без региона» (`*`) или «по умолчанию».
3. Иначе — регион по умолчанию из настроек радио; если он пуст, пакет уходит без региона.

Регион сообщения фиксируется при постановке в очередь, повторы идут с тем же регионом. Пакеты напрямую
(direct) и zero-hop региона не несут, как в штатной прошивке. Приём не зависит от регионов: плата видит
весь эфир. Своя ретрансляция платы (relay) регионы не проверяет, как у штатного companion.

Пока регионы настроены не у всех репитеров маршрута, сообщения с регионом могут не дойти. Тогда
задайте каналу «без региона» (`*`) или очистите регион по умолчанию.

| Где | Регион по умолчанию | Регион канала | Поиск |
|---|---|---|---|
| Экран M9, T-Deck | «Настройки → Радио → Регион»: OK — ввод имени, ← → — найденные | карточка канала, строка «Регион»: ← → — по умолчанию, без региона, найденные; OK — сохранить или ввести имя | «Радио → Найти регионы» |
| Экран Heltec, GAT562, T114 и других однокнопочных плат | «Радио → Регион»: перебор «нет» и найденных | — (веб-страница или приложение) | «Радио → Найти регионы» (удержание) |
| Веб-страница и приложение MeshMesh | «Настройки → Радио → Регион» с подсказкой найденных | карточка канала, раздел «Регион» | «Радио → Регионы → Найти регионы» |
| Приложение MeshCore | «Регион по умолчанию» (`CMD_SET_DEFAULT_FLOOD_SCOPE` / `GET`) | «Задать область региона» чата (регион сеанса перед отправкой) | «Поиск регионов» (управляющие пакеты и анонимные запросы) |
| USB / BLE | `set {"region":"msk"}`, `""` — нет | `channel do {"action":"region","channel":ID,"region":"msk"}`, `""` — по умолчанию, `"*"` — без региона | `regions find`, `regions` |

Ссылка канала несёт его регион в параметре `region_scope` (формат MeshCore App 1.47+): вступление по
такой ссылке или QR-коду сразу задаёт каналу регион. Регион «без региона» в ссылку не попадает.

Хранение: регион по умолчанию — ключи `region` и `region_key` в NVS (`meshmesh`); регионы каналов —
отдельной записью `meshmesh-mc/ch_regions` (ID канала и регион); список каналов `channels` остался в прежнем
формате, поэтому при откате на прошивку до 0.15.0 каналы сохраняются.

### Поиск регионов

Плата отправляет zero-hop запрос обнаружения репитеров (управляющий пакет `0x80`, фильтр «репитер»),
8 с собирает ответы (до 8 репитеров; если не ответил никто — рассылает обнаружение ещё раз), затем каждому по очереди — анонимный запрос «регионы»
(`ANON_REQ_TYPE_REGIONS`, ответ zero-hop); промолчавшему репитеру запрос повторяется один раз. Репитер отвечает списком регионов, у которых разрешён flood;
`*` в список выбора не попадает. Всего до 12 имён. Поиск длится от 35 с (один репитер) до минуты; поздние ответы засчитываются ещё 30 с: загруженный репитер ставит ответ в очередь.

Отвечают только репитеры, которые слышат плату напрямую. Штатный репитер отвечает не больше чем на
4 анонимных запроса за 3 минуты от всех узлов вместе, поэтому частые повторы поиска возвращают пустой
список. Репитеры в контакты не добавляются: ответ
расшифровывается ключом из ответа на обнаружение, поэтому поиск работает и при заполненной таблице контактов.

## Режим репитера и комнаты

В серверном режиме MeshMesh работает CLI MeshCore 1.17 (`src/MeshServer.cpp`, `docs/repeater.md`), в том
числе все команды `region`. Команды вводятся: по USB — `server cli <команда>`, на веб-странице —
консоль CLI, в приложении MeshCore или с другой платы MeshMesh — после входа администратора.

Пример для сети Московского региона (схема сообщества: `ru` → `mow` → `msk` или `mosobl` → округ или
сектор). Ретранслятор в пределах МКАД, Северный округ:

```
region allowf *
region def ru mow msk sao
region
region save
```

Вывод `region` после настройки:

```
*^ F
 ru F
  mow F
   msk F
    sao F
```

Тот же результат по шагам (синтаксис 1.15 и старше):

```
region allowf *
region put ru
region put mow ru
region put msk mow
region put sao msk
region allowf ru
region allowf mow
region allowf msk
region allowf sao
region save
```

Округа Москвы: `cao`, `sao`, `svao`, `vao`, `uvao`, `uao`, `uzao`, `zao`, `szao`. Сектора области (после
`mosobl`): `sever`, `severo-vostok`, `vostok`, `yug`, `zapad`. Ошибочный регион удаляется командой
`region remove имя`, сначала дочерние. Ретранслятору задают только регионы, где он стоит: узел на
границе может иметь два, а узел со всеми регионами снова собирает одну большую сеть.

Репитер MeshMesh отвечает на поиск регионов и пересылает пакеты по своим регионам так же, как штатный.

## Проверено (9 октября 2026, Heltec V4, прошивка 0.15.0, загрузки 211–215)

`tools/region_check.py --port PORT` по USB, кадры из `txframe`, код региона пересчитан независимо на Python:

- объявление с регионом по умолчанию — `TRANSPORT_FLOOD`, код совпал; неверное имя отклоняется;
- канал со своим регионом, «без региона» (обычный flood) и «по умолчанию» — коды совпали;
- приложение: чтение и запись региона по умолчанию (63/64, в том числе закрытый ключ), регион сеанса (54)
  и флаг «без региона», управляющий пакет (55);
- поиск по реальной сети (Казань): сторонний репитер MeshCore трижды прислал регионы `ru`, `ru-ta`,
  `ru-ta-kazan`, в том числе при заполненной таблице контактов (24 из 24; контакты не изменились); в другом
  прогоне ответили 3 репитера, один — без настроенных регионов (только `*`). Примерно в половине из
  ~12 поисков репитеры не отвечали на обнаружение или на запрос регионов (лимиты штатного репитера —
  4 обнаружения за 2 минуты и 4 анонимных запроса за 3 минуты на всех, — и эфир); после этого добавлены
  повтор обнаружения и повторный запрос промолчавшему репитеру, их доля успеха отдельно не измерена;
- регион канала (в том числе Public) сохраняется после перезапуска; при откате на старую прошивку список
  каналов читается, так как формат `channels` не изменён;
- веб-страница через `tools/web_usb_bridge.py` в браузере: поле «Регион» в настройках радио (сохранение и
  очистка), поиск с прогрессом, регион в карточке канала (`sao`, `*`, сброс; неверное имя отклоняется) —
  проверены по DOM и ответам платы, снимок страницы не делался;
- QEMU: образ T-LoRa (классическая ESP32, буферы поиска в куче) загружается, `regions`, `config`, `channels`
  отвечают.

Экраны — предпросмотр `tools/ui_preview` (M9, T-Deck, Heltec, GAT562, T114).
