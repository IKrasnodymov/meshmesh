# MeshMesh для Android

Приложение показывает веб-интерфейс самого устройства (`web/index.html` — тот же файл, из
которого собирается `include/PortalPage.h`) и подключается к плате тремя способами:
Wi-Fi, Bluetooth LE и USB. Все разделы страницы — чаты, узлы, карта, навигация, связь,
радар и датчик движения, модули, настройки, «Косынка» и шахматы — работают по любому из них.

Исходники — `android/`, пакет `org.meshmesh.app`, Android 10 и новее (minSdk 29, targetSdk 35).

## Сборка и установка

```sh
cd android
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew testDebugUnitTest assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
```

Сборка копирует `web/index.html` в ресурсы приложения, поэтому интерфейс приложения всегда
совпадает с веб-страницей прошивки той же ревизии. Публичная версия Android задаётся независимо
от прошивки в `versions.properties`. Выпуск 0.4.0 имеет имя `0.4.0+<versionCode>`, где код CI —
`1000000 + run_number * 100 + run_attempt` (Gradle получает его через `MM_VERSION_CODE`).
Локально — `0.4.0+local`, код 1000000. См. [версии и публикацию](releases.md).
Локальный пакет `release` без ключа проекта подписан отладочным
ключом и устанавливается напрямую. APK на сайте собирает GitHub Actions и подписывает ключом
проекта (`MM_KEYSTORE`, `MM_KEYSTORE_PASSWORD` из секретов), чтобы новые версии ставились поверх. В отладочной сборке
включена отладка WebView (`chrome://inspect`).

## Как устроено

- `MainActivity` — WebView со страницей и `assets/host.js`, `assets/host.css`: экран
  подключения вместо формы пароля и перехват `fetch('/api/…')`. Остальные запросы (OpenStreetMap
  при подготовке карты) идут в интернет телефона как обычно. Загрузка карты выбирает файл
  системным диалогом, «скачать» сохраняет файл через диалог Android.
- `MeshService` — служба переднего плана: держит соединение в фоне, при свёрнутом приложении
  раз в 8 с читает `status` и при росте RX — историю; новые входящие сообщения становятся
  уведомлениями (нажатие открывает чат); уведомление на каждую партию (ход соперника, вызов, ничья,
  итог; нажатие открывает доску), шахматы проверяются сразу после приёма платой и не реже раза в 32 с.
- Время в чате — время приёма сообщения платой (для своих — время отправки), для прошлых дней
  с датой. Если часы платы не заданы (Heltec и другие платы без RTC после перезапуска), приложение
  при подключении один раз ставит время телефона командой `clock`; сообщения, принятые до этого,
  остаются без времени.
- Ответ на сообщение — свайп пузыря справа налево, как в Telegram (на компьютере — двойной щелчок).
  Отдельного поля ответа в MeshCore нет, ответ — обычный текст: в канале на чужое сообщение он
  начинается с упоминания `@[Имя] `, иначе — со строки-цитаты `> начало сообщения` до 40 байт.
  Страница показывает цитату блоком и выделяет упоминание; экраны плат показывают текст как есть.
- `Updater` — обновление самого приложения с сайта. Сайт публикует `app/version.json` (номер,
  имя, размер и SHA-256 APK; `tools/app_release.py`) и копию `app/meshmesh-<номер>.apk`. При запуске
  приложение читает описание; если номер больше своего — карточка «Обновить» на экране подключения и
  в «Подключениях» (там же «Проверить обновления»). APK скачивается в кеш, сверяется по размеру и
  SHA-256 и передаётся установщику Android; он один раз просит разрешить установку из MeshMesh и
  сам проверяет подпись. Обновления включены только в сборке, подписанной ключом проекта.
- `flash/` — прошивка платы ESP32 по USB с сайта: «Подключения → Прошивка платы» при связи по USB
  (или через мост на компьютере). `FirmwareUpdate` берёт `firmware/boards.json` и `manifest.json` платы —
  те же четыре файла и смещения, что пишет установщик в браузере (без метки языка), — и проверяет их
  (загрузчик DIO, таблица разделов, приложение). `EspLoader` говорит с загрузчиком ROM, как esptool 5.4
  без стаба: вход DTR/RTS (у Heltec — последовательность USB Serial/JTAG), проверка чипа, на USB
  Serial/JTAG — отключение сторожевых таймеров RTC, 460800 бод для USB-UART, сжатая запись блоками
  по 1 КБ, MD5 каждой области, выход сторожевым таймером (Heltec) или EN. NVS (ключ, настройки,
  контакты), LittleFS (история) и язык не затрагиваются. Затем приложение подключается снова.
  Обрыв посреди записи оставляет плату в загрузчике ROM: «Повторить» прошивает заново. Heltec V4 и
  V4 R8 сообщают одну плату — ревизию выбирает объём PSRAM. GAT562 (nRF52): `NrfDfu` — касание на
  1200 бод, загрузчик появляется отдельным USB-устройством (Android спрашивает доступ к нему прямо во
  время обновления), затем последовательный DFU, как `site/nrf52dfu.js` (пакеты совпадают байт в байт,
  `NrfDfuTest`): пишется только приложение — образ с тем языком экрана, что уже на плате (`langs` в
  статусе, `lang_images` сайта), — хранилище платы и метка языка `--` остаются. Пока идёт
  обновление, приложение не подключается само к появляющимся устройствам.
- `api/HttpApi` — Wi-Fi: HTTP-сервер устройства (`src/Portal.cpp`) с Basic-авторизацией.
- `api/CommandApi` — USB и BLE: каждый запрос страницы становится той командой, которую
  выполняет HTTP-обработчик устройства (`executeCommand`), с теми же кодами ответа.
- `link/` — каналы: `UsbLink` (usb-serial-for-android), `BleLink` (GATT), `TcpLink` (мост
  на компьютере); `LineTransport` — одна команда за раз, одна строка ответа.

### Wi-Fi

Точка доступа устройства (`MM-XXXXXX`, WPA2, 192.168.4.1) подключается из приложения через
`WifiNetworkSpecifier`: Android показывает свой запрос, сеть используется только приложением,
мобильный интернет остаётся для остального. Пароль — на экране устройства; если раньше
подключались по USB или BLE при включённой точке, приложение уже знает пароль этой загрузки
(он меняется при каждом запуске устройства). «Другой адрес» — устройство или мост в сети,
к которой телефон уже подключён.

### Bluetooth LE

Сервис `7a9e0001-…`: команда пишется в RX с подтверждением (до 255 байт), ответ приходит
уведомлениями TX и заканчивается переводом строки. Обе характеристики требуют
аутентифицированного сопряжения: при первом подключении Android просит PIN с экрана
устройства. PIN создаётся один раз и хранится в настройках платы. BLE включён по умолчанию в обычном режиме
(в режимах репитера и комнаты — выключен, чтобы плата могла спать), а выбор пользователя сохраняется
после перезапуска (кроме перезапуска после сбоя). Если телефон помнит сопряжение, которого у платы уже нет (её flash заменили),
приложение удаляет старую связку и просит PIN заново. BLE медленнее остальных каналов, поэтому
списки (история, узлы, шахматы, настройки) перечитываются только при изменении `status` или
раз в 20 с, а обновление страницы идёт раз в 4 с.

### USB

M9 (мост CH340, 1A86:7522) и Heltec V4 (встроенный USB ESP32-S3, 303A:1001) через OTG.
Линии управления как в `tools/device.py`: у M9 DTR и RTS выключены, у Heltec DTR включён —
подключение платы не перезапускает. M9 переводится на 921600 бод (как `tools/maps.py`), раз в
3 с простоя приложение шлёт `\r`, чтобы плата не вернулась к 115200; при сбое скорости — откат
на 115200 и повтор команды. При подключении платы кабелем Android предлагает открыть приложение,
и оно подключается само.

## Команды прошивки для приложения

Добавлены в `executeCommand`, поэтому доступны по USB, BLE и `/api/command`:

| Команда | Ответ | Зачем |
|---|---|---|
| `connections` | JSON: SSID, пароль Wi-Fi, PIN BLE | раньше только по USB; теперь и по сопряжённому BLE |
| `radar web` | JSON `/api/radar?open=1` | открывает и удерживает радар (10 с), с именами сетей, как веб-страница |
| `radar do {JSON}` | `OK …` / `ERR …` | действия `/api/radar`: track, untrack, peak, csi, calibrate, close |
| `map tile Z X Y OFFSET [LEN]` | `OK tile SIZE OFFSET BASE64` | файл тайла с SD частями до 6144 байт |
| `sendjson {"to":…,"text":…}` | как `send` | текст с переводом строки, который не помещается в командную строку |
| `channels` | JSON `/api/channels` | каналы MeshCore; сопряжённому клиенту — со ссылками закрытых каналов |
| `channel do {JSON}` | `OK …` / `ERR …`, для `probe` — JSON | действия `/api/channels`: add, remove, invite, probe |
| `pet` | JSON `/api/pet` | питомец: состояние и рисунок 16×16 (раздел «Питомец», [pet.md](pet.md)); действия — `pet adopt`, `release`, `cuddle`, `feed`, `heal`, `name`, `mortal` через `/api/command` |

Диагностическая команда `radar` по-прежнему не выводит имён сетей и устройств; `radar web`
выводит их, как страница по Wi-Fi. BLE-ответ теперь отправляется уведомлениями размером
согласованного MTU (до 244 байт вместо 20) и только при свободных буферах NimBLE
(`os_msys_num_free`), иначе уведомление отложено: потерянный фрагмент испортил бы ответ.

Прочитанные тайлы карты кешируются на телефоне (до 200 МБ); копия используется, пока
заголовок тайла на SD (размер и CRC) не изменился, поэтому повторный просмотр по BLE быстрый.

## Каналы MeshCore: QR-код и ссылки

Список каналов по BLE кешируется, как узлы, и перечитывается после любого действия или при
изменении числа каналов в `status`. Приглашение в канал — ссылка
`meshcore://channel/add?name=…&secret=…`; приложение принимает её двумя путями:

- `MeshNative.scanQr()` — страница открывает сканер QR-кодов (zxing-android-embedded, без
  сервисов Google). Разрешение на камеру запрашивается при первом сканировании.
- Ссылка из камеры телефона или мессенджера открывает приложение (intent-filter
  `meshcore://channel`).

Обе дороги ведут в `MeshHost.channelLink(text)` (`assets/host.js`): текст другого вида
отклоняется («Это не ссылка на канал MeshCore»), ссылка передаётся странице
`openChannelLink(link)`, которая спрашивает подтверждение. Пока плата не подключена, ссылка
ждёт подключения; ссылка из запуска приложения не повторяется при пересоздании экрана.

## Проверка на компьютере

```sh
.venv/bin/python tools/usb_tcp_bridge.py --port /dev/cu.wchusbserial110   # USB-протокол на :8771
.venv/bin/python tools/web_usb_bridge.py --port /dev/cu.usbmodem101 --http 8093  # HTTP API
```

В эмуляторе компьютер виден как 10.0.2.2: «USB → USB через компьютер» проверяет командный
слой (тот же код, что для USB и BLE на телефоне) с настоящей платой, «Wi-Fi → Другой адрес»
— HTTP-клиент. Мост USB держит 115200 бод и отказывает в смене скорости. Для прошивки клиент
начинает со строки `MMRAW1`: мост передаёт байты как есть, управляет DTR/RTS и скоростью и сам
открывает порт заново, если плата с native USB пропала с шины после перезапуска; для nRF52 он сам
делает касание на 1200 бод и переходит на порт загрузчика, а после обновления — обратно.

Модульные тесты (`./gradlew testDebugUnitTest`) проверяют то, что ломается незаметно:
разрезанный UTF-8 в уведомлениях, строки журнала среди ответов, JSON-ответ, разорванный
строкой журнала драйвера Wi-Fi, поздний ответ команды после таймаута, лимит 255 байт BLE при
загрузке карты, перевод строки в сообщении, коды ответа, сборку тайла, кеш списков BLE и команды
каналов (JSON страницы в одну строку, ответ `probe`, старая прошивка).

## Ограничения

- Плата nRF52 (GAT562), с которой телефон был сопряжён под прежней прошивкой, приходит с
  устаревшим кэшем сервисов Android; приложение сбрасывает его и ищет сервисы заново
  (`docs/gat562.md`).

- Обнаружение пакетов, совместимость и радиопараметры — как у прошивки (`docs/verification.md`).
- Загрузка карты по BLE — около 2 КБ/с (по 180 байт на запись); большой пакет приложение
  предлагает загрузить по USB или Wi-Fi.
- Строка `wifi:timeout when WiFi un-init` драйвера ESP32 иногда попадает внутрь ответа по USB
  (после закрытия радара); приложение распознаёт обрезанный JSON и повторяет команду.
- Одна плата за раз; переключение — «Связь → Отключиться».
- Прошивка по USB проверена из эмулятора через мост на Heltec V4 (USB Serial/JTAG; обрыв посреди
  записи и «Повторить») и M9 (USB-UART CH340, 460800 бод): запись, MD5, перезапуск, повторное
  подключение; ключ, настройки, история, NVS, SD и карта сохранены. GAT562 (nRF52) на плате не
  проверен. USB OTG на телефоне (в том числе запрос доступа к устройству, появившемуся после
  перезапуска) и классический ESP32 не проверены.
- Сканер QR-кодов и ссылки `meshcore://` проверены в эмуляторе (запрос камеры, отказ, открытие
  сканера, ссылка до и после загрузки страницы); распознавание настоящего QR-кода камерой
  телефона не проверено.
