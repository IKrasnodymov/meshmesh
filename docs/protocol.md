# MeshMesh MM/1

Пакет: заголовок 36 байт, до 180 байт зашифрованной полезной нагрузки,
16-байтный GCM tag. Максимум 232 байта. Все целые little-endian.

| Смещение | Размер | Значение |
|---|---|---|
| 0 | 2 | ASCII `MM` |
| 2 | 1 | Версия `1` |
| 3 | 1 | Тип: Message=1, Ack=2, Hello=3, Position=4 |
| 4 | 4 | Первые 4 байта SHA-256 от сетевого ключа |
| 8 | 8 | Адрес отправителя: ESP32 eFuse MAC как uint64 |
| 16 | 8 | Адрес получателя; `ffffffffffffffff` — всем |
| 24 | 4 | Счётчик загрузок, сохранённый в NVS перед радиообменом |
| 28 | 4 | Счётчик пакетов в текущей загрузке, начиная с 1 |
| 32 | 1 | Максимальное число пересылок, 0–7 |
| 33 | 1 | Текущее число пересылок |
| 34 | 1 | Длина полезной нагрузки |
| 35 | 1 | Зарезервировано, всегда 0 |

AES-256-GCM использует сетевой ключ 32 байта. IV 16 байт состоит из
source:uint64 + session:uint32 + sequence:uint32. AAD — все байты заголовка,
кроме текущего числа пересылок (байт 33). Ограничение числа пересылок
аутентифицировано, а текущее число может увеличивать промежуточный узел.
Неаутентифицированная часть и ограниченный кэш не защищают от злонамеренного
сброса номера перехода или повторной отправки старого пакета после перезапуска.

Каждый пакет проверяется по размеру, версии, типу, сети, диапазонам переходов,
GCM tag и структуре полезной нагрузки до отображения и ретрансляции.
Пакеты иных протоколов не принимаются.

## Полезная нагрузка

- Message: id:uint32, name_length:uint8, name UTF-8 (1–24 байта),
  text UTF-8 (1–151 байт). Первая попытка использует id равный sequence;
  повторы получают новый sequence при том же id сообщения.
- Ack: исходная session:uint32 + id сообщения:uint32. Только адресный ACK
  от ожидаемого получателя меняет статус на DELIVERED.
- Hello: имя UTF-8 (1–24 байта).
- Position: широта:int32 × 1e7, долгота:int32 × 1e7, время UTC:uint32.

Дедупликация пакетов по source/session/sequence; сообщений по
source/session/message_id. Повтор сообщения может вызвать новый ACK, но
не второе отображение. Пересылка случайно откладывается; адресный получатель
исходный пакет дальше не пересылает. Каждая новая попытка имеет новый sequence,
поэтому промежуточные узлы могут переслать её снова.

LoRa PHY: private sync word `0x12`, явный заголовок, CRC, preamble 12,
по умолчанию 868.731 МГц / BW62.5 / SF8 / CR4/6 / 10dBm, максимум 3 пересылки.
Адреса и имя сети видны в заголовке, текст и имя отправителя находятся под GCM.

Смена/сброс NVS с сохранённым старым ключом может повторить IV. После удаления
NVS или восстановления старого образа MeshMesh нужно создать новый ключ сети.
