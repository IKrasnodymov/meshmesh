# Сеть города

Радиопрофиль местной сети MeshCore (частота, полоса, SF, CR) можно выбрать по справочнику городов, а не вводить
вручную. Это делается на сайте, на веб-странице устройства и в приложении для Android. Справочник ведёт сообщество:
[VoxMesh/meshcore-local-networks](https://github.com/VoxMesh/meshcore-local-networks). Ошибки и новые города
присылайте туда через Issues.

## Что меняется

Только четыре общих для сети параметра: частота, полоса, SF и CR. Мощность, пересылки, предел ретрансляции,
регион, ключи и контакты остаются прежними. Установка прошивки радионастройки не меняет. Профиль записывается
в плату только тогда, когда человек сам выбрал сеть и подтвердил запись.

MeshMesh работает в диапазоне 863–870 МГц с полосой 62.5, 125, 250 или 500 кГц. Сети вне этого диапазона
(например, 433 МГц) показываются, но записать их на плату с MeshMesh нельзя.

## Справочник

- Копия справочника — `site/networks.json`. Сайт берёт её рядом со страницей, приложение вшивает её в APK, прошивка ESP32
  отдаёт её странице по Wi-Fi (`/networks.json`, `tools/pio_web.py`).
- Кнопка «Обновить справочник» скачивает текущий `catalog.json` с GitHub и сохраняет его в браузере (или в
  WebView приложения). Используется более новая из двух копий по полю `updated`. При каждом открытии справочник
  из интернета не загружается.
- Копию обновляет `tools/networks.py update`, проверяет `tools/networks.py check` (входит в проверки Pages).
- Список упорядочен по расстоянию, если известно положение, иначе в порядке справочника. Под городом показаны
  его сети и сети родительской территории (`parent_id`). Поиск идёт по названию города и региона.
- Положение берётся из GPS платы (только доверенный фикс), из телефона в приложении (приблизительного достаточно)
  или из браузера. Страница платы, открытая по Wi-Fi (http), геопозицию браузера не получает: город можно найти
  по названию.

## Сайт

Блок «Сеть города» находится в разделе установки (`site/netpick.js`) и виден только на русской версии сайта
(справочник пока описывает сети России). Он свёрнут: в заголовке видна выбранная сеть, по нажатию раскрываются два шага.

1. Выберите сеть: строка на сеть — город, название, параметры, расстояние после «Рядом со мной», ссылка на
   сообщество. Сначала показаны пять строк, поиск по городу или региону показывает и сети окружающей территории.
   Выбор хранится в браузере (`localStorage`) и не сбрасывается, если перезагрузить страницу,
   прошить следующую плату, повторить прошивку или выбрать другой тип платы. Повторное нажатие снимает выбор.
   Если в справочнике у выбранной сети поменялись параметры, сайт покажет новые и предложит их взять.
2. Закройте окно установки (порт должен быть свободен) и нажмите «По USB» или «По Bluetooth».
   Сайт работает через протокол MeshCore companion, поэтому подходит и для MeshMesh 0.9.0+, и для штатной
   MeshCore companion.
3. Сайт показывает имя, модель и прошивку платы, а также текущие и новые параметры. Если частота сети в другом
   диапазоне, чем текущая частота платы (433 / 868 / 915 МГц), запись станет доступна после отметки
   «Плата и антенна рассчитаны на … МГц». На плату с MeshMesh частоту вне 863–870 МГц записать нельзя.
4. «Записать в эту плату» — подтверждение для каждой платы. Сайт сверяет записанное, запоминает прежние настройки
   этой платы (по её ключу) и отключается, после чего можно подключать следующую. При повторном подключении
   той же платы появится кнопка «Вернуть прежние».

Флаг ретрансляции клиента штатной MeshCore (`client repeat`, прошивка 9+) отправляется таким, каким был.

## Страница устройства и приложение

В «Настройки → Радио» есть блок «Выбрать сеть по городу» (`renderNet` в `web/index.html`). Выбранная сеть
показывает, что изменится. «Применить» нажимается дважды, как другие опасные действия страницы.

С прошивкой 0.27.0 доступен режим «Протестировать». В нём настройки применяются, но не сохраняются:

- **Оставить** — сохранить их;
- **Вернуть** — вернуть сохранённые;
- **Проверить** — спросить репитеры, которые слышат плату напрямую (тот же запрос, что поиск регионов), и показать,
  сколько ответило. Решение принимает человек: автоматического отката по тишине нет.

Если плату перезапустить во время теста, вернутся сохранённые настройки.

Плата запоминает профиль до последней смены частоты, полосы, SF или CR. «Вернуть прежние» возвращает его, а текущий
становится прежним. Изменение через companion (приложения MeshCore, сайт) тоже запоминается.

## Плата

- Команды USB/BLE/HTTP (`/api/command`): `radio try {"frequency":868.731,"bandwidth":62.5,"sf":7,"cr":7}`,
  `radio keep`, `radio revert`, `radio previous` (`src/App.cpp`, `radioCommand`).
- `config` выдаёт `radio_prev` (прежний профиль) и `radio_trial` (сохранённый профиль во время теста).
- Тест живёт только в памяти: `Config::save` пишет в NVS сохранённый профиль, пока тест не подтверждён. Прежний
  профиль хранится в NVS под ключом `radio_prev`.
- На экране: M9 и T-Deck — строка «Прежнее радио» / «Тест радио» в настройках радио (OK — вернуть или оставить),
  однокнопочные платы, GAT562 и T114 — строка «Прежние» / «Тест» в редакторе радио (удержание).

## Поиск сети в эфире (0.29.0)

Плата сама находит, какой профиль справочника слышен рядом (`src/NetFind.inc`, `include/NetFind.h`). Прошивка несёт
выжимку справочника: места и профили диапазона 863–870 МГц (`include/NetCatalog.h`). Её пишет `tools/networks.py update`
вместе с `site/networks.json`, а `tools/networks.py check` сверяет её с копией.

Как идёт поиск:

1. Первым слушается текущий профиль, затем профили-кандидаты. Если известно положение, это сети мест в радиусе 150 км,
   от ближайшего к дальнему (с сетями родительской территории). Если положения нет или выбран режим «Все профили»,
   плата перебирает все профили справочника: чаще встречающиеся идут первыми. Профили с одинаковыми частотой, полосой
   и SF проверяются один раз: приёму CR не мешает.
2. На каждом профиле плата перестраивает трансивер без записи в настройки (`MeshRadio::tune`), отправляет zero-hop
   запрос обнаружения репитеров (тот же, что в поиске регионов) и 8 с слушает. Считаются ответившие репитеры
   (с лучшим SNR) и остальные принятые пакеты.
3. После последнего профиля возвращается сохранённый. Лучшим считается профиль, у которого больше репитеров,
   а при равенстве — больше пакетов. Если он лучше текущего, плата предлагает его.
4. Найденную сеть применяет только человек, и только как тест (`radio try`): «Оставить» сохраняет её, перезапуск
   возвращает прежнюю.

Пока идёт поиск (от 10 с до 4–5 минут), наши сообщения ждут в очереди, ретрансляция выключена, а сеть сохранённого
профиля не слышна. Пакеты, принятые на чужом профиле, обрабатываются обычным образом: объявления узлов добавляют их
в контакты. Поиск работает только в обычном режиме, не одновременно с поиском регионов. Если в это время меняются
настройки радио, поиск прекращается.

Штатный репитер отвечает не больше чем на 4 запроса обнаружения за 2 минуты от всех узлов вместе. Отвечают только
репитеры в прямой слышимости. Сеть, где есть только компаньоны без репитеров, видна лишь по принятым пакетам.

**Сам по себе** (`net_auto`, включён по умолчанию). Раз в 30 с плата проверяет положение: свежий GPS-фикс (дата не
раньше сборки) или положение телефона из приложения. Если ближайшее место справочника не дальше 150 км и текущий
профиль не входит в его сети, плата один раз за загрузку для этого места ищет сети ближайших мест. О найденной сети
сообщает экран: «Рядом сеть: Москва… SF7». Во время теста радио автоматический поиск не запускается.

Где искать:

- M9 и T-Deck: «Настройки → Радио → Найти сеть». OK запускает поиск (или останавливает его), а после находки
  включает тест найденной сети; ← → — поиск по всем профилям.
- Однокнопочные платы, GAT562 и T114: строка «Найти сеть» в редакторе радио (удержание — то же, что OK).
- Веб-страница и приложение: блок «Поиск сети в эфире» в «Настройки → Радио»: «Искать рядом» (с положением,
  найденным кнопкой «Рядом»), «Все профили», таблица ответов и «Тест» у каждого профиля, переключатель
  «Искать самой рядом с другим городом».
- USB/BLE/HTTP: `netfind` (состояние и результаты JSON), `netfind start`, `netfind start all`,
  `netfind start LAT LON`, `netfind stop`, `netfind use N` (тест результата N); `set {"net_auto":false}`.

Поле `path_hash_bytes` справочника (размер хэша пути сети) прошивка пока не применяет: хэш пути настраивается
отдельно, по умолчанию 2 байта.

## Проверено

- Прошивка собрана для M9, Heltec V4, Heltec V3, T-Deck, GAT562 и T114; экраны радио проверены в `tools/ui_preview`.
- Страница: выбор, тест, «Оставить», «Вернуть» и «Вернуть прежние» проверены в браузере с `tools/web_demo.py`.
- Сайт: выбор сохраняется после перезагрузки страницы.
- M9: команды `radio …`, откат теста перезапуском, строка на экране, запись по протоколу companion через USB (как делает
  сайт) и страница с настоящей платой (через `tools/web_usb_bridge.py`). Подробности — `docs/verification.md`.
- 0.29.0, поиск сети: прошивка собрана; экраны в `tools/ui_preview` (M9, T-Deck, Heltec, GAT562, T114), страница с
  `tools/web_demo.py`. Поиск на настоящих платах, ответы репитеров на чужом профиле и автоматический поиск по GPS
  не проверены.
- Не проверены: другие платы, запись из настоящего браузера по Web Serial/Bluetooth, штатная MeshCore, ответ репитеров
  на «Проверить» и положение телефона в приложении.
