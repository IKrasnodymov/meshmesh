# Heltec Mesh Node T114 (nRF52840)

Вторая плата MeshMesh на nRF52840 (1 МБ flash, 256 КБ RAM, Bluetooth) после GAT562: SX1262,
цветной TFT 1.14" 240×135 (ST7789), одна кнопка USER, зелёный светодиод, GNSS L76K (в
комплектации с GPS), разъём аккумулятора. Цель PlatformIO `heltec_t114`, плата —
`boards/meshmesh_heltec_t114.json`, вариант ядра — `variants/heltec_t114` (из MeshCore), выводы —
`include/BoardPins.h`, аппаратный слой — `src/nrf52/HardwareT114.cpp`. Хранилище, Bluetooth,
радар, USB и установка — общий слой nRF52, как у GAT562 ([gat562.md](gat562.md)).

## Что есть и чего нет

| Функция | T114 |
|---|---|
| Чаты MeshCore: общий канал, каналы и личные, ACK, повторы, история | есть |
| Узлы, объявления, сброс пути | есть |
| Шахматы с контактами на экране, одной кнопкой | есть, цветная доска 128×128 |
| Режимы репитера и комнаты MeshCore | есть |
| Радар: BLE-устройства и LoRa-узлы, пеленг | есть; Wi-Fi нет |
| GPS (L76K), часы по GPS | есть, если модуль установлен |
| Bluetooth LE для приложения Android (сопряжение по PIN), USB-команды | есть |
| Wi-Fi: точка доступа, веб-страница по Wi-Fi, интернет, Wi-Fi-радар, CSI | нет: в nRF52840 нет Wi-Fi |
| Офлайн-карты, экранная клавиатура | нет (нет SD; одна кнопка) |

## Экран

Логика интерфейса — та же однокнопочная, что у Heltec V4 (`src/UiHeltec.cpp`): те же страницы, меню,
действия, тексты и шахматы. Рисует их на T114 отдельный слой `src/UiHires.inc` в родном разрешении
240×135 и в стиле M9 (`src/Ui.cpp`): цвета M9 (`include/Palette.h`), те же иконки
(`include/UiIcons.h`, общие с M9), тёмные скруглённые карточки, бирюзовая полоска у выбранной строки,
аватары узлов и каналов, шапка с заголовком, непрочитанными, Bluetooth, GPS, сигналом, часами и
батареей (при длинном заголовке пропадают процент батареи, затем значок Bluetooth), внизу —
подсказки-«клавиши» «клик → следующий экран» и «держ → действие». Главная — карточка узла с частотой и
счётчиками TX/RX и три плитки: чаты, узлы, шахматы. Сообщение — отправитель с аватаром и текст в
«пузыре» (свои — тёмно-бирюзовые), узел — карточка с типом, сигналом и расстоянием, радар — список с
цветом по виду сигнала, пеленг — уровень, тренд и пик.

Текст: 9×15, 10×20 (жирный — двойной отрисовкой, только для имён: на плотных буквах он слипается),
7×13 и inr24. Глифы, которых в этих шрифтах нет (CJK, арабский, расширенная латиница), рисуются в
натуральный размер подмножествами шрифтов 12–20 px из образа — по высоте как заглавные 10×20.

Шахматы занимают весь экран: доска 128×128 (клетки 16×16 в классических цветах, силуэты фигур 12×13,
белые — с тёмным контуром, жёлтые точки на доступных клетках, голубой курсор, подсветка последнего
хода), справа — соперник, цвет, состояние, выбранный ход в плашке, последний ход и свои подсказки.

Буфер — 240×135 по байту на пиксель (индекс палитры, 32 КБ вместо 64 КБ RGB565); `flush()` отправляет
на панель только изменившиеся строки по SPIM3 на 32 МГц. Монохромные платы этот слой не используют,
их экраны не изменились (побайтно совпадают в `tools/ui_preview`). Скриншот по USB
(`tools/device.py --screenshot`) отдаёт 240×135 RGB565; плата преобразует палитру на лету, потому что
64 КБ одним куском в куче nRF52 не выделяются. Предпросмотр на компьютере —
`tools/ui_preview/build.sh t114 OUTDIR [LANG]` (однокнопочный сценарий Heltec с его проверками).

### Питомец

Экран «Питомец» идёт после «Шахмат»: зверёк в цвете на карточке (масштаб 5, 80×80 точек, цвет тела —
по виду), «облачко» с репликой поверх имени, полосы сытости, радости и здоровья со значками; яйцо
показывает время до вылупления, умерший — надгробие. Удержание кнопки открывает меню «Погладить»,
«Кормить», «Лечить», «Смерть: вкл./выкл.» (у надгробия — «Новое яйцо»). Цвета питомца добавлены в палитру
(тело и акцент каждого из 15 видов, `include/Palette.h`). Самый большой языковой образ T114 (китайский) с питомцем оставляет
8 КБ flash. На плате (7 октября) проверены экран, меню и «Погладить» USB-клавишами; кнопка и приём
по радио с питомцем не проверялись. Эмулятор — `tools/ui_preview/build.sh t114`; подробности —
[pet.md](pet.md).

## Управление

Как у Heltec V4: **клик** — следующий экран или пункт меню, **удержание ~1,2 с** — действие экрана или
его меню. Шахматы: на своём ходу клик перебирает фигуры, которые могут ходить, затем «Меню партии»,
удержание берёт фигуру; затем клик перебирает клетки, куда она может пойти, затем «Отмена»,
удержание делает ход. Первые 5 секунд после загрузки — выбор режима работы.

## Ожидание и энергосбережение

При погашенном экране основной цикл nRF52 ожидает до 20 мс вместо опроса каждые 2 мс.
Прерывание LoRa немедленно уведомляет задачу; сам сон процессора обслуживают FreeRTOS и
SoftDevice. При передаче/очереди пакетов, радаре и в течение 1 с после USB/BLE-команды или
кнопки сохраняется быстрый цикл. Между ожиданиями обслуживаются кнопки, USB и GPS;
приём LoRa остаётся непрерывным. `status`: `idle_waits`, `idle_wait_ms`, `idle_radio_events` —
число ожиданий, их суммарная длительность и уведомления LoRa, полученные в ожидании.
Это не измерение времени сна CPU или потребляемого тока; `sleeps`/`sleep_ms` относятся к ESP32.
RXPS и периодическое отключение GPS пока не включены.
Ориентир для следующих этапов — [тесты EasySkyMesh](https://github.com/IoTThinks/EasySkyMesh/wiki/PowerSaving#3-test-results);
их значения тока не являются измерениями MeshMesh. Проверка: `tools/power_check.py --port PORT`
(с `--peer PORT` дополнительно проверяется приём объявлений LoRa во время ожидания).

## Память и хранилище

Разметка flash, SoftDevice (S140 6.1.1) и загрузчик совпадают с GAT562: приложение 0x26000–0xD4000,
LittleFS MeshMesh 0xD4000–0xED000, InternalFS ядра 0xED000–0xF4000, загрузчик UF2 Heltec
(«HT-n5262», версия 0.9.0) с 0xF4000. Образ содержит английский, русский и ещё один язык экрана
(`lang/<код>/`); корневой образ ~634 КБ из 712, китайский — самый большой. На плате есть внешняя
QSPI-flash 2 МБ (MX25R1635F); MeshMesh её пока не использует.

USB: прошивка — 239a:8071, загрузчик — 239a:0071 (как у Adafruit: у приложения бит 0x8000). Штатная
Meshtastic представлялась как 239a:4405; MeshMesh этот PID не использует, чтобы сайт, приложение и
`tools/nrf52.py` различали прошивку и загрузчик одинаково для всех плат nRF52.

После Meshtastic или MeshCore в области 0xD4000 лежат чужие байты: MeshMesh их не трогает, ключ не
сохраняется и передача выключена, пока не создать хранилище («Модули → Создать хранилище…» или
USB-команда `fsformat`, затем `restart`).

## Установка

- **Из браузера** (Chrome или Edge на компьютере): сайт, плата Heltec T114, «Установить» — как у
  GAT562. Плату с другой прошивкой сначала переводят в загрузчик двойным нажатием RESET.
- **Диск UF2**: дважды быстро нажать RESET — появится диск `HT-n5262`; скопировать на него
  `firmware.uf2`.
- **Обновление MeshMesh**: `python tools/nrf52.py flash artifacts/meshmesh-heltec-t114-<версия>` —
  касание 1200 бод переводит плату в последовательный DFU, запись `firmware-dfu.zip`, сверка хэша
  сборки. Инструмент требует копию в `backups/t114/` и сверяет `board` работающей платы с пакетом.
- **Резервная копия**: `python tools/nrf52.py backup` при смонтированном диске загрузчика —
  `CURRENT.UF2` (0x1000–0xEA000) в `backups/t114/` (по Board-ID диска), права 0600.

## Выводы

По вариантам MeshCore (`heltec_t114`) и Meshtastic (`heltec_mesh_node_t114`): LoRa — SPI (SCK P0.19,
MOSI P0.22, MISO P0.23, NSS P0.24, DIO1 P0.20, BUSY P0.17, RESET P0.25), TCXO 1,8 В, DIO2 —
антенный ключ. TFT — SPI1 (SCK P1.08, MOSI P1.09), CS P0.11, DC P0.12, RESET P0.02, питание
VTFT_CTRL P0.03 и подсветка P0.15 (обе активны низким уровнем, подсветка — ШИМ). Кнопка P1.10,
светодиод P1.03 (активен низким). Батарея — AIN2 (P0.04) через делитель ×4,9, включается P0.06.
GPS: питание VEXT P0.21, RX P1.05 ← TX модуля, TX P1.07 → модуль, RESET P1.06 (активен низким),
STANDBY P1.02 (высокий — не спать). В варианте MeshCore `SX126X_POWER_EN=37` совпадает с линией
GPS P1.05; MeshMesh этот вывод не дёргает, радио запускается и без него.

## Проверено 5 октября 2026

Плата пользователя (T114 V2 с GPS), до этого — Meshtastic 2.7.15. Копия исходной flash —
`backups/t114/` (`CURRENT.UF2`, два чтения совпали). Установка через диск UF2, затем обновления по
касанию 1200 бод и последовательному DFU — хэш сборки совпадал каждый раз. После `fsformat`:
хранилище и радио работают, батарея 4,06–4,11 В, GPS передаёт NMEA (в помещении без фиксации).
Владелец подтвердил: изображение не перевёрнуто, не сдвинуто, цвета правильные; клик и удержание
кнопки работают. Через USB-события кнопки сняты все страницы, на компьютере пройден однокнопочный
сценарий с шахматами (`tools/ui_preview`). Радиообмен проверен 5 октября с Heltec V4 по LoRa (сборка
`bf91eaa`): объявления в обе стороны, личные сообщения в обе стороны с ACK по одной копии, партия на рейтинг с
подписями, сверка журналов (9 записей, в том числе чужих партий) и турнир с T114-организатором —
`docs/verification.md`. Не проверено: сопряжение с телефоном, установка с сайта в браузере, GPS под открытым небом, гашение экрана и яркость на глаз.
